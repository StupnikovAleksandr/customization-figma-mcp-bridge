# Проверка сайта по Figma

Для проверок в рабочей папке MCP использовать [стандарт отчёта](../../AUDIT-REPORT-STANDARD.md). В качестве образца HTML использовать `assets/compare.html`.

## Допуск пользователя

- **Разница до 3 CSS px включительно не считается ошибкой.** Применять допуск к измеренным координатам, размерам, отступам, межстрочным интервалам, размерам шрифта и другим величинам в пикселях.
- Сравнивать абсолютную разницу по каждому параметру: `abs(сайт − макет) <= 3`. Использовать исходные числа до округления для отображения.
- Значения в пределах допуска можно оставлять в таблице исходных измерений с пометкой «В пределах допуска». Не включать их в список ошибок, карточки замечаний, число дефектов и рекомендации обязательных исправлений; не подсвечивать как ошибки.
- Расхождения более 3 px рассматривать как кандидаты в замечания после проверки сопоставимости элементов, состояния и масштаба.
- Допуск относится к величинам в CSS-пикселях. Функциональные ошибки, отсутствующие элементы, неверные тексты, цвета и единицы, не выраженные в пикселях, оценивать по существу.

## Проверка и результат

Читать все выбранные адаптивы и состояния. Задавать viewport по фактическим ширине и высоте фрейма. Для геометрии Figma учитывать абсолютные bounds и преобразования; перед снимками дожидаться загрузки используемых изображений, шрифтов и завершения переходов.

Осматривать каждую пару скриншотов, включая фон, кадрирование и иконки. Разделять измеренные отклонения и визуальные наблюдения; не объявлять совпадение изображений только на основании координат контейнеров.

Сохранять отдельную папку аудита с `compare.html`, `REPORT.md`, `measurements.json` и PNG-парами 1×. В HTML включать выбор адаптива/слайда, просмотр рядом, наложение с прозрачностью, масштаб 1:1 и таблицу дельт. Указывать допуск 3 px в отчёте и JSON. Не включать учётные данные в артефакты.
