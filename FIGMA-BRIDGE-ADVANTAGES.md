# Figma MCP Bridge и официальный Figma MCP

Проект основан на [Figma MCP Bridge от gethopp](https://github.com/gethopp/figma-mcp-bridge): development plugin в Figma Desktop передаёт данные локальному MCP-серверу. Официальный Figma MCP — другой способ передать агенту контекст дизайна.

## Практические преимущества Bridge

| Возможность | Польза |
| --- | --- |
| Чтение через локальный плагин | Не расходует квоту вызовов официального Figma MCP |
| Выделение и дерево слоёв | Удобно получать структуру и стили нескольких адаптивов |
| Экспорт изображений на диск | PNG сразу доступны для локальных сравнений |
| Открытые исходники | Можно добавлять команды под процесс команды |
| Несколько подключённых файлов | Выбор по fileKey при запущенном плагине в каждом файле |

Чтение текущего выделения само по себе не уникально: оно доступно также через официальный desktop MCP. Инструменты Bridge и ограничения записи описаны в [его README](figma-mcp-bridge/README.md).

## Ограничения

Bridge требует Figma Desktop, запущенный плагин, локальный сервер и поддержку зависимостей. Локальное соединение с Figma не делает весь аудит автономным. Удобство экспорта и настройки не гарантирует большей точности сравнения.

Возможности официального сервера и условия доступа меняются: смотри [документацию инструментов](https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts/) и [лимиты доступа](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/). Редактирование Figma не следует считать уникальным преимуществом Bridge.

## Кто выполняет проверку

Bridge читает макет и сохраняет экспорт. Playwright открывает сайт, измеряет DOM/CSS и делает снимки. Codex сравнивает данные, проверяет поведение и оформляет выводы. Сам Bridge сайт не проверяет.

Аналогичный аудит можно построить на официальном Figma MCP и браузерных инструментах. Этот репозиторий полезен, если нужны доступные исходники, локальный экспорт и единый процесс.
